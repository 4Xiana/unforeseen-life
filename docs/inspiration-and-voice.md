# 灵感收藏与吱呀语音

手册新增「灵感收藏」。用户可输入自己的任务想法，或粘贴文章、视频文案和公开链接。AI 整理为一条可实践任务，用户可以修改标题和玩法，再确认收藏。整理失败时保留输入；输入和预览在本设备保存草稿。收藏保存原文、来源链接、读取到的正文和任务结构，不将收藏视为完成记录，也不覆盖喜好档案。

`server/inspiration.ts` 使用独立 SQLite 文件，按 clientId 隔离。确认收藏支持重复请求去重；支持暂停、恢复及确认移除。客户端身份与现有应用一致，属于设备身份，不等同于账户认证。

推荐时混入一条符合空闲时间、场景、人数、预算及体力的收藏，并保留普通任务和心愿章节选项。每条冷却 30 分钟。未明确预算时仅推荐零额外花费任务；有自由文本雷点时由当前推荐模型确认不冲突并以原 id 提名，服务端再检查客观限制。选中后保留任务描述和材料快照，沿用现有步骤设计、原始证物验收及存档流程。

公开链接读取仅支持 HTTP(S)，每次跳转重新解析 DNS、拒绝内网和本机地址，并将请求绑定到已校验 IP。限制跳转、时间及正文大小。不能读取登录态内容、图片内文字或视频画面；正文不足或访问受限时要求用户粘贴相关文案。输入中已有足够正文时直接按粘贴内容整理，并明确提示链接未能读取，不编造原文。

`POST /api/tts` 在服务端调用 MiniMax，返回 MP3。默认模型 `speech-2.8-turbo`、声音 `qiaopi_mengmei`（俏皮萌妹）。服务端配置 `MINIMAX_API_KEY`、`MINIMAX_TTS_MODEL`、`MINIMAX_VOICE_ID`、`MINIMAX_API_BASE`；密钥仅放在忽略提交的 `server/.env` 中。客户端不持有密钥。

通话使用同一个 Audio 元素顺序播放，支持加载反馈、试听和播放失败重试。静音、开麦、切换轮次、退出或切到后台时停止音频、取消请求并使迟到结果失效。移动端通过用户点击试听启用音频播放；浏览器禁止自动播放时显示点击播放提示。

验证：`server/node_modules/.bin/tsx --test tests/inspiration.test.ts`；前后端分别执行构建。`tests/inspiration-ui-check.mjs` 覆盖四种尺寸的收藏、暂停、恢复、原文、草稿及推荐流程；`tests/minimax-voice-ui-check.mjs` 验证迟到响应、开麦、重试与退出；`tests/minimax-live-playback-check.mjs` 实际调用服务验证浏览器解码、播放及停止。后者会使用配置的 MiniMax 服务生成一段语音。浏览器脚本通过 `PLAYWRIGHT_MODULE` 指定本机 Playwright，并先启动 `tests/goal-preview.mjs` 隔离存储与聊天模型。

本次验证结果：18 项灵感/语音识别检查通过；12 项既有心愿计划回归通过；320×568、390×844、844×390、1280×900 的收藏界面与交互通过。真实语音返回 MP3，浏览器 readyState=4、音频时长 5.1 秒，退出后停止。预览已更新至 `http://localhost:5183/unforeseen-life/`。
