# 长程支线实现约定

配套产品方案：`long-term-quests.html`。沿用 React/Vite、Express、SQLite、匿名 clientId 和 S0–S3 任务流程。喜好档案继续描述稳定偏好，长程目标拥有独立章节与记录。

## 数据与生成

- 新增独立 GoalStore，使用 `XIAN_DATA_DIR/goals.sqlite`，不让 SessionStore 的重启恢复逻辑被额外连接触发。
- Goal 保留既有数据结构；前端创建/修改仅填写愿望，普通生成的补充字段清空，默认 15 分钟、场景不限。AI 读取长期喜好档案安排具体任务；动机与目标专属偏好不再要求用户填写。
- Plan：成果说明、3–6 个有序章节；每章有标题、目的、前序关联、成果、场景/时长、2–4 个 text/photo 证据步骤。
- 章节确认前生成草稿并持久化。结构校验失败或模型请求失败返回明确错误，保留输入。提供少量人工设计的完整示例计划，只有用户显式选择示例时使用；自定义目标调用现有 OpenAI 兼容端点生成结构化计划。
- 自定义生成读取长期喜好档案与目标补充，不修改档案。校验包括常见跨日等待、纯确认式证物与明确不拍照的限制；失败最多请求模型修正一次，再次失败不落盘。规则不能覆盖全部自然语言语义。
- 示例入口先填写表单；修改草稿使用事务原位更新。生成期间如果另一个标签页已确认，迟到的结果不得覆盖已开启的计划。
- 章节步骤在确认计划时定稿，实际执行保留既定成果与验收要求。用前序真实证物补充上下文与提示，不允许模型更换成无关任务。
- 完成记录含 goalId、chapterId、sessionId、完成日期、每步指引及原始证物。唯一键 goalId+chapterId 保证幂等。

## 推荐与执行

- 为 ActivityPlan 增加可选 journey 元信息，不改变普通活动字段。
- propose_activities 在服务端混入合格的下一章；随机、时长、场景、暂停、冷却由服务端决定，不交给提示词猜测。
- 每批最多一项，保留普通选项；明确主动推进时绕过概率与冷却，但仍检查用户归属及条件。
- 在 select_activity 重新验证章节仍是当前可接取章节，防止旧卡片、多标签页与跨会话重复推进。
- 模型漏调工具时的确定性选卡兜底也必须 claim，不能绕过暂停、归属或会话占用检查。
- design_activity_steps 对长程卡使用服务端保存的章节步骤。publish_step 使用已设计步骤的规范内容，避免模型重新改写验收标准。
- S3 前核对所有步骤已保存有效证物，再结算章节。普通对话不能直接修改章节进度。
- 结算、解锁与奖励在 GoalStore 事务内完成。持久化会话为 S3 但尚未结算时可根据快照补结算；重复恢复不重复发奖。
- Agent 上下文只注入相关目标、章节目标、前序真实记录，原文仍永久保留在数据库中。

## 界面与恢复

- 首页/聊天统一为「我的手册」入口；PersonalLibrary 共用纸页外壳，收纳喜好、长程、手账三个页签。各功能支持 embedded 模式，不叠加独立弹层；切换时保留表单与页面状态，保存喜好后就地提示。
- 长程页：列表、创建/草稿预览、详情。详情含进度、状态、主动推进、暂停/恢复、章节与成果证物、目标专属纪念章。
- 请求失败保留输入、显示重试；关闭弹层不取消已保存的数据。
- 长程卡显示归属、章节和承接关系。所有使用 ActivityCards 的聊天/抽屉/沉浸页同步受益。
- JourneyContext 共用于推荐卡、聊天步骤、任务抽屉、通话步骤；展开时用 `GET /api/goals/:id` 校验归属并读取完整原文与原图。步骤事件及驳回重发均携带 journey；升级前的执行中会话从快照补回元信息。
- 完成事件刷新长程数据，刷新页面读取服务器进度；不重复弹出旧奖励。
- 下载记录导出用户实际成果文字与照片引用，不输出虚构完成内容。

## 验证重点

用户隔离；草稿确认；重启持久化；下一章顺序；概率边界；冷却；场景/时间不符；暂停/恢复；前序证物承接；全部证物通过才结算；同章重复完成不增加进度；最终纪念章与成果记录；无目标用户仍能使用原流程；移动端创建/预览/详情及刷新恢复。

## 实现入口

- `server/goals-types.ts`：前后端共用的类型定义（前端仅 type import）。
- `server/goal-planner.ts`：自定义 AI 计划、结构校验与显式示例。
- `server/goal-store.ts`：SQLite、随机筛选、会话接取、事务结算、奖励、恢复与前序证物上下文。
- `server/index.ts`：`GET/POST /api/goals`、`POST /api/goals/:id/status`；用户归属使用 `X-Client-Id`。
- `src/components/GoalsView.tsx`：创建、预览、章节记录、暂停/恢复、续接与下载；`goals.css` 为纸页布局。
- `src/components/PersonalLibrary.tsx`：统一手册入口的三栏目容器、键盘页签导航与焦点管理；`personal-library.css` 处理共享外壳及嵌入布局。
- `tests/longTermGoals.test.ts`：存储、调度、验收与工具护栏测试。
- `tests/goal-preview.mjs`：真实存储/路由/工具配合确定性模型替身的隔离 UI 环境。

章节接取状态绑定会话；关闭页面不释放。用户主动放下任务时释放；再次进入长程页可打开旧会话继续。完成结算在发出 S3 状态事件之前发生，章节记录带会话 ID 并去重；读取长程列表时也检查尚未结算的 S3 快照。

## 验证记录

- 12 项长程测试、6 项会话持久化回归通过。覆盖草稿修改及并发确认、档案生成上下文、有限修正、跨日/拍照/纯确认护栏、旧会话元信息恢复和确定性选卡兜底。
- 浏览器通过实际点击验证示例目标确认、第一章两步提交、1/3 进度与「第一片拼图」、原始证物回看及刷新后第二章可用。
- 4 组屏幕尺寸通过创建、关闭后保留草稿、暂停/恢复、时长不足禁用、刷新及无横向溢出检查；按钮高度至少 44px，输入字号 16px。
- PRD 中三组交互示例已通过浏览器检查。
- 浏览器验收使用确定性模型替身，实际模型的创意质量和真实证物判断仍取决于配置的 OpenAI 兼容服务；没有把模拟生成作为模型质量验证。
- `goal-journey-check.mjs` 实际点击通过示例填表、拒绝空泛完成声明、三章逐步提交、聊天/抽屉/通话的前序原文、刷新恢复、三枚奖励及导出原文完整性。
- 配置中的真实模型已返回通过校验的「窗边光影观察册」样本：5 章、每章 8–10 分钟、全部文字证物；实测也暴露过跨日任务和违反拍照雷点的输出，已增加相应护栏。单个样本通过不代表全部创意质量或真实验收质量已充分验证。
- 后端构建复制全部 Markdown 手册，生产产物已检查能加载 6 份手册。
- `http://localhost:5183/unforeseen-life/` 已重新构建并验证首页、长程 API 和示例填表无页面错误；远程服务器未在本轮部署。
